Procedure

Follow these systematic laboratory steps to complete the experiment and observe how Django routes and processes requests across Function-Based Views and Class-Based Views.

Laboratory Protocol

  1. Step 1: Read Aim and Conceptual Objectives

    Begin by reviewing the Aim page to understand the purpose of comparing FBVs and CBVs in Django's MVT pattern.

  2. Step 2: Study the Theory Foundation

    Carefully read the Theory page to examine the internal request-response lifecycle, procedural method branching in FBVs, and OOP method dispatching with as_view() in CBVs.

  3. Step 3: Complete Pretest Evaluation

    Answer the diagnostic questions in the Pretest to verify prerequisite understanding of the HttpRequest object and view return types.

  4. Step 4: Launch the Interactive Simulation

    Navigate to the Simulation tab. Select either Function-Based View or Class-Based View from the simulation control panel.

  5. Step 5: Configure and Transmit HTTP Requests

    Select an HTTP Method (GET, POST, PUT, or DELETE), optionally specify query parameters or payload data, and press Send Request.

  6. Step 6: Trace the Execution Lifecycle

    Observe the highlighted request path through Django components: URLconf Resolution → Middleware → View Handler → Method Dispatcher → Template/Response Generation.

  7. Step 7: Analyze Code & Output Comparison

    Inspect the side-by-side execution trace showing how the FBV (imperative if/elif) contrasts with the CBV (declarative method dispatching).

  8. Step 8: Assessment and Feedback

    Proceed to the Posttest to assess concept retention, review references, and provide feedback on the experiment.
